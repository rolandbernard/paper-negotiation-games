\subsection{Prompt Templates}\label{sec:dond_prompt_templates}

The english prompt templates for both players of the Deal or No Deal game are given in \cref{fig:dond_prompt_template} and \cref{fig:dond_prompt_template_proposal}.

The game is started by the game master by sending to both players a message following the prompt template shown in \cref{fig:dond_prompt_template}. For this, the variables enclosed in \$ characters are replaced as follows.
\begin{enumerate}
  \item \$N\$ is replaced with the maximum number of turns before the game master will instruct the players to submit a proposal. For all instances evaluated in this work this has been set to $5$.
  \item \$GOAL\$ is replaced with the goal that the players are trying to optimize. This depends only on the game mode. In the semi-competitive mode it is given as "\emph{Your goal is to maximize the score you receive.}". On the other hand, in the cooperative mode the goal is given as "\emph{Your goal is to maximize the sum of your score and the score of the other player.}".
  \item \$ITEMS\$ is replaced with the set of available items, e.g., "\emph{1 book, 2 hats, 2 balls.}". This value is always the same for both players.
  \item \$VALUE\_FUNCTION\$ is replaced with the value function for one of the players, e.g., "\emph{book: 0, hat: 1, ball: 4.}". Each player gets a different value function, and so the prompts for the two player differ.
\end{enumerate}

When the maximum number of turns has been reached, i.e., each player has sent 5 messages, the game master will instruct the player that is up next that he must now submit a proposal by using the prompt shown in \cref{fig:dond_prompt_template_timeout}. If the next message does not contain a correctly formatted proposal the game is aborted.

If one of the two players makes a proposal, either proactively or because they were instructed to by the game master, the game master will instruct the remaining player to also make a proposal. For this the template shown in \cref{fig:dond_prompt_template_early} is used. Again, the next message must be a proposal or the game is aborted.

\subsection{Overall Results}

\Cref{fig:dond_playedquality} shows the average quality scores and percentage of played game for each model for the DoND game, averaged over the different game modes and languages.

We can observe that most models achieve a high percentage of played games, meaning that they are able to accurately follow the instructions. The only exception to this are the Llama model and the Nematron model with reasoning enabled. The models GPT-5, GPT-5 mini, and Claude 4 with reasoning enabled show the strongest performance. 

Generally we can see that the models perform better with reasoning enabled than with it disabled. While the difference between reasoning and non-reasoning is small for the Claude 4 model, reasoning gives a large performance improvement for the GPT-5 and GPT-5 mini, as well s the Qwen-3 model.

To better understand the performance of the models, we show more detailed breakdown by language and game mode in \cref{tab:dond-detailed-results}. These results are further depicted in \cref{fig:dond_perlanguage}, which show the performance differences between experiments for English, German and Italian tasks.

We can see here again that most models are good at following the instructions. We can also see that the reason that the Nematron model with reasoning enabled has such a low percentage of played games overall is that it has not played a single game in German correctly, while its percentage of played game is otherwise comparable to Llama. By inspecting the transcripts of some games played by Nematron in German it becomes clear that the reason for the aborted games is that Nematron always made the proposal in English, whereas it should have made it in German. This is likely because by Nematron also seems to exclusively reason in English.

Except for some outlier we also generally see that performance in the cooperative and semi-competitive game modes are comparable, but overall achieving slightly higher quality scores for the cooperative mode (49\%) as compared to the semi-competitive mode (46\%). The number of aborted games is consistent at 8\% between both game modes on average.

Performance was generally highest in English. On average across all models the clemscore for English was 49 while it was 43 and 40, respectively for German and Italian. Because of the issues of the Nematron model in German, the number of aborted games is higher in German, with 13\% as compared to 6\% for both English and Italian. However, in German the average quality score for the played games is higher at 49\% compared to the average of 43\% for Italian.

We can analyse the results also based on the outcome that was achieved. This is depicted in \cref{fig:dond_outcome}. We separate between four possible game outcomes. The game can either end with complementary proposals or not. If there is a valid agreement, it could either be with the optimal score, i.e., a quality score of 100, with an agreement that reached a suboptimal score less than 100. Finally, if there is no valid agreement it can either be because of conflicting proposals, or because the game was aborted due to rule violations.

Particularly for GTP-5 and GPT-5 mini this problem is largely solved by using the reasoning models, as opposed to the non-reasoning versions.

In the analysis of the cooperative game mode shown in \cref{tab:dond-game-outcomes-coop} we can see some significant differences in strategies between the different models. We see that both GPT-5 models, with reasoning disabled, will explicitly often explicitly discuss how to achieve a maximum score, i.e., they will talk about having to give each item to the player that values it most. This is in contrast to for example Claude 4 or the GPT-5 models without reasoning enabled, as those models will often just follow a generic negotiation routine, trying to obtain a "fair" agreement.

We can further observe that a main reason for the low scores of the non-reasoning versions of the GPT-5 models is that they submit the wrong proposal. This means that the proposal they submit to the game master is often not the one they discussed with the other player in the natural language messages. This manifests sometimes as submitting the proposal for the other player, sometimes as proposals that include the complete set of items, and other times even completely unrelated proposals. Deepseek v3.1 also suffers for a less ever version of this problem.

Lastly, some other models like Deepseek distilled Llama and the Nematron models, as well as the Qwen-3 model without reasoning often submit proposals before discussing and agreeing to a division with the other player. This is particularly severe for the Nematron models as these nearly always submit a proposal as the first message, without exchanging any messages with the other player. Looking at the reasoning traces we can observe that the Nematron model does not seem to understand that it can communicate with the other player, expressing correctly that it does not know the other players values, but not realizing that it could ask for them.

For the semi-competitive game mode we see largely the same results, with the main difference being that the GPT-5 models now no longer try to explicitly discuss maximizing their score. This makes sense as the setting is no longer cooperative, so it is no longer purely advantageous to share such reasoning with the other player. Another difference to the cooperative mode is that the GPT-5 mini model with reasoning and the GPT-OSS model not make the wrong proposals more often. It is unclear why this happens.

We can also generally see an increase in the amount of suboptimal outcomes. Interestingly this is not necessarily because of unclear preferences, but because models are often requesting items that have no value to them, or leave some items unclaimed by either player, sometimes even expressing the intention of doing so deliberately. Keeping an item that does not have any value does not make much sense for any of the players, as giving up that item could have instead be used as leverage for getting some other items.
